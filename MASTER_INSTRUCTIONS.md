## ФАЗА 1: НАСТРОЙКА BCD И ЗАГРУЗЧИКА

### Шаг 1.1: Получить GUID записей загрузки

На сервере 185.244.175.90 выполните:

```cmd
bcdedit /enum
```

Найдите и запишите:
- **{GUID основной системы}** - запись с текущей Windows (обычно помечена как `{default}` или `{current}`)
- **{GUID клона}** - запись, которая только что была добавлена (последняя в списке)

**ПРИМЕР ВЫВОДА:**
```
Диспетчер загрузки Windows
---------------------------
идентификатор              {bootmgr}
...

Загрузка Windows
----------------
идентификатор              {abc12345-1234-1234-1234-123456789abc}  <-- ЭТО ОСНОВНАЯ СИСТЕМА
description                Windows Server 2019
device                     partition=C:
...

Загрузка Windows
----------------
идентификатор              {def67890-5678-5678-5678-567890abcdef}  <-- ЭТО КЛОН
description                Windows Server 2019
device                     vhd=[C:]\VMClone\clon192-4.vhdx
...
```

### Шаг 1.2: Настроить BCD для безопасной загрузки

Замените `{GUID_ОСНОВНОЙ_СИСТЕМЫ}` и `{GUID_КЛОНА}` на реальные GUID из предыдущего шага:

```cmd
REM Установить основную систему по умолчанию (для безопасности)
bcdedit /default {GUID_ОСНОВНОЙ_СИСТЕМЫ}

REM Настроить запись клона
bcdedit /set {GUID_КЛОНА} device vhd=[C:]\VMClone\clon192-4.vhdx
bcdedit /set {GUID_КЛОНА} osdevice vhd=[C:]\VMClone\clon192-4.vhdx
bcdedit /set {GUID_КЛОНА} description "Clone Server (IP 194.31.72.192)"
bcdedit /set {GUID_КЛОНА} detecthal yes

REM Настроить безопасную загрузку (без меню, таймаут 0)
bcdedit /timeout 0
bcdedit /set {bootmgr} displaybootmenu no

REM Игнорировать ошибки загрузки (автоматически загружаться даже при сбоях)
bcdedit /set {default} bootstatuspolicy ignoreallfailures
bcdedit /set {GUID_КЛОНА} bootstatuspolicy ignoreallfailures
```

### Шаг 1.3: Проверить конфигурацию

```cmd
bcdedit /enum
```

Убедитесь что:
- `{default}` указывает на основную систему
- Запись клона имеет `device` и `osdevice` с путем к VHDX
- `timeout` = 0
- `displaybootmenu` = No

## ФАЗА 4: НАСТРОЙКА WIREGUARD

### Шаг 4.1: Сгенерировать ключи WireGuard

На сервере 185.244.175.90 (если WireGuard уже установлен):

```cmd
generate-wireguard-keys.bat
```

Или вручную:
```cmd
wg genkey > clone-private.key
type clone-private.key | wg pubkey > clone-public.key
```

Запишите:
- **ПРИВАТНЫЙ КЛЮЧ КЛОНА** (для конфигурации клона)
- **ПУБЛИЧНЫЙ КЛЮЧ КЛОНА** (для конфигурации эталона)

### Шаг 4.2: Получить публичный ключ эталона

На сервере 194.31.72.192:

```cmd
wg show
```

Запишите **ПУБЛИЧНЫЙ КЛЮЧ ЭТАЛОНА** (строка "public key:")

### Шаг 4.3: Обновить wg-clone.conf

Откройте файл `wg-clone.conf` и замените:
- `CLONE_PRIVATE_KEY_HERE` → приватный ключ клона
- `ETALON_PUBLIC_KEY_HERE` → публичный ключ эталона

### Шаг 4.4: Обновить конфигурацию WireGuard на эталоне

На сервере 194.31.72.192 добавьте в конфигурацию WireGuard:

```ini
[Peer]
PublicKey = CLONE_PUBLIC_KEY_HERE
AllowedIPs = 10.0.0.2/32
```

Замените `CLONE_PUBLIC_KEY_HERE` на публичный ключ клона.

Перезапустите WireGuard на эталоне:
```cmd
wg-quick down wg0
wg-quick up wg0
```

(или через GUI WireGuard)

## TROUBLESHOOTING

### Проблема: Не могу подключиться по RDP после загрузки клона

**Решение:**
1. Подождите 2-3 минуты (система может загружаться дольше при первом запуске)
2. Проверьте что сервер не перезагрузился обратно в основную систему
3. Если доступа нет через 5 минут, выполните жесткую перезагрузку - система вернется к основной (default)

### Проблема: curl ifconfig.me показывает 185.244.175.90 вместо 194.31.72.192

**Решение:**
1. Немедленно выполните `C:\EMERGENCY_RETURN.bat`
2. После возврата в основную систему проверьте:
   - Скрипт блокировки файрвола настроен на автозапуск?
   - WireGuard установлен и туннель активирован?
3. Исправьте проблемы и попробуйте снова

### Проблема: Клон не загружается, система возвращается к основной

**Решение:**
1. Проверьте VHDX не поврежден: попробуйте смонтировать в основной системе
2. Проверьте BCD: `bcdedit /enum` - запись клона присутствует?
3. Проверьте логи: `bcdedit /enum {GUID_КЛОНА}`

### Проблема: WireGuard туннель не работает

**Решение:**
1. Проверьте конфигурацию на эталоне: `wg show` на 194.31.72.192
2. Проверьте ключи совпадают
3. Проверьте firewall на эталоне разрешает UDP 51820
4. Проверьте `ping 10.0.0.1` из клона
